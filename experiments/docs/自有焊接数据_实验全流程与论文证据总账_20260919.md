# 自有焊接数据：实验全流程、论文证据总账与补实验清单

> 更新：2026-09-19  
> 目的：把已完成实验按统一口径归档，明确“已经证实什么、尚未证实什么、论文还必须补什么”。本文不是把不同实验的最好数字拼在一起，而是保留每个数字的评价协议与适用范围。

## 0. 先给结论

你的自有数据实验已经形成了一条清楚的、符合长尾问题机制的链路：

```text
源图像级划分
  → 圆环焊道 ROI 展开（不拉伸）
  → 150 px 循环重叠滑窗
  → D-FINE-S 生成高召回候选
  → IBO 候选区域（内部 I / 边界 B / 周边 O）
  → 可靠性重评估与低分真候选保护
  → 环向跨窗同类归并
  → 正常参照 / 局部频率证据
  → 尾类—相似头类的对比纠错
  → 统一的头、中、尾类与错误类型评价
```

已经最可靠地验证的是三件事：

1. **不拉伸的 150 px 循环滑窗显著降低第一阶段漏检**，因此解决了“后续模块没有候选区域可分析”的前提问题。
2. **IBO 可靠性重评估能够把低置信的真实候选保留下来**；在高置信 D-FINE 基线的评价协议下，纯尾类正确率从 15.15% 提升到 39.39%。
3. **跨滑窗同类归并可以消除循环滑窗的重复框，并进一步减少漏检**；对小焊烟、焊洞长等类别有明确收益。

但论文写作必须如实保留两个限制：

- 在 2026-09-12 的统一 A0--A4 消融中，单独加入 IBO、正常参照或频率证据后，**没有超过采用同一候选池的 D-FINE A0**。这说明目前的正常参照/频率实现已显示候选级可分性，却尚未证明它们带来独立的最终实例级总体收益。
- 针对“焊灰色 ↔ 缺焊长塌族”的混淆纠错，焊灰色由 55.56% 提高到 88.89%，但总体准确率从 93.58% 降到 93.05%。它是“以少量头类代价换尾类”的定向校准证据，而不是所有类别同时提升的证据。

因此，当前最准确的论文主张应是：

> 所提出流程通过几何保真候选生成、候选级可靠性重评估与混淆类定向校准，缓解了长尾焊接缺陷在固定高置信阈值下的漏检和少数类被相似多数类吸收的问题；正常参照与频率证据的最终增益仍需在独立测试集和严格消融中进一步验证。

## 1. 证据分级：写论文时怎样使用这些结果

| 分级 | 含义 | 当前对应结果 | 论文中的正确用法 |
|---|---|---|---|
| A：已验证的开发证据 | 有固定输入、明确规则与可复查明细 | 150 px 几何改造；D-FINE 候选覆盖；IBO reliability；跨窗归并；A0--A5 消融 | 可写“验证集开发实验表明”；不能直接写成最终盲测结论 |
| B：候选级有效、实例级待证 | 候选 AUROC/AUPR 良好，但阈值回投未优于输入 | 正常参照—频率 group evidence v2 | 可写为“候选可靠性证据”；不能单独宣称最终检测精度提升 |
| C：机制性/定向证据 | 只针对特定混淆对，存在头尾权衡 | 焊灰色对比纠错 | 可用作长尾混淆案例；需报告对头类的代价 |
| D：尚未完成 | 论文设想存在，当前未完成与公式等价的端到端实现 | query 内双域融合、覆盖度协方差分布校准 DSC、独立盲测 | 不能写成“已实现并验证”，应作为后续补实验或删除/收缩表述 |

**最重要的防错原则**：所有阈值、合并参数、尾类纠错器若在当前验证集上选择，就只能称为开发集结果。正式论文还要冻结这些参数，并在从未参与任何选择的测试集上仅评估一次。

## 2. 数据、划分与评价对象

### 2.1 数据形态与源图像级切分

原始对象是圆环形焊道图像。先按**源图像**完成 train/validation 划分，再对各自图像展开、切片；不能先切 tile 再随机划分，否则同一焊道相邻片段会同时进入训练和验证，形成信息泄漏。

当前 150 px 训练数据的可复查统计如下：

| 项目 | 数量 |
|---|---:|
| 原始训练源图像 | 3,099 |
| 原始训练标注实例 | 6,263 |
| 与焊道区域相交的实例 | 4,710 |
| 在展开切片中表示的实例 | 4,707 |
| 原始训练 tiles | 20,982 |
| 其中空白 tiles | 17,079 |
| 去重筛选后的训练 tiles | 5,855 |
| 其中空白 tiles | 1,952（33.34%） |
| 筛选后训练标注 | 6,855 |
| 当前验证集非钢帽缺陷实例 | 1,124 |

长尾不是由一个统一数字定义，而是由训练频次与实际错误模式共同定义。当前常用的低频观察对象包括小焊烟、焊灰色、焊缝蓝黑、焊坑、缺焊裂、焊高缝等。它们在验证集中合计很少，个别类只有 1--2 个实例，因此单类百分比必须同时报告原始分子/分母。

### 2.2 评价口径

当前已有两类评价，二者都应保留，不能相互替代。

| 评价 | 作用 | 当前规则 |
|---|---|---|
| COCO 风格检测指标 | 衡量框定位与分类整体性能 | mAP@[.5:.95]、AP50、AP75、AR100 |
| 工业实例审计指标 | 对细长、碎片化焊道缺陷更可解释 | 正确 / 错类 / 漏检；同类框覆盖 GT 面积 ≥20% 可视为有效覆盖；错类辅助 IoU 阈值 0.50 |

除特别说明外，实例审计主表排除钢帽类别。当前不同报告还使用了两种类别合并口径：

- 烟类合并：`焊烟 / 小焊烟 / 焊烟团` 或其中一部分的家族匹配；
- 易混长条族：`断焊 / 长焊高塌 / 缺焊蓝黑`（部分报告还含相关扩展类别）按同族匹配。

它们适合**候选定位**和对长条缺陷碎片化的公平审计，但正式类别级 AP 表必须同时给出严格原始类别结果；不能只报合并后的结果。

## 3. 阶段 I：几何保真输入与高召回 D-FINE-S 候选生成

### 3.1 做了什么

圆环焊道以 ROI 的内外圆环带展开为直线带状图。展开后的有效高度固定为 150 px，沿环向切为宽 1024 px 的窗口：

| 参数 | 设置 |
|---|---:|
| 有效焊道高度 | 150 px |
| 实际 D-FINE 输入 | 1024 × 160（只在底部补 10 px） |
| 滑窗宽度 / stride | 1024 px / 768 px |
| 相邻重叠 | 256 px |
| 首尾处理 | cyclic tiles，首尾连续 |
| 标注保留阈值 | min-visible = 0.5 |
| 空白片段处理 | MD5 + 感知哈希去重，保留多样正常负样本 |

关键不是“把图做得更大”，而是**不把 150 px 径向带强行缩放到 256 px**。此前径向 1.71 倍放大会改变焊高纹、长焊高塌、缺焊蓝黑等细长纹理的形态；新版只补边，不缩放框和纹理。

训练模型为 D-FINE-S / HGNetv2-B0，23 类，batch size 4，32 epochs；最佳 checkpoint 位于 epoch 14。主学习率 1e-4、backbone 学习率 5e-5，AdamW，MultiStepLR（20、28 epoch 衰减）。最佳 COCO 指标为 mAP 0.1905、AP50 0.3424、AP75 0.1784、AR100 0.6793。

### 3.2 它怎样改善长尾问题

尾类第二阶段的前提不是“先分类正确”，而是“至少出现一个可分析候选”。150 px 循环滑窗首先解决的是候选缺失。

| 一阶段模型 | 正确 | 错类 | 漏检 | 实例有效覆盖率 |
|---|---:|---:|---:|---:|
| 圆环版 | 864 | 53 | 207 | 76.87% |
| 展开初版 | 893 | 63 | 168 | 79.45% |
| 长上下文版 | 884 | 54 | 186 | 78.65% |
| **150 px 循环滑窗** | **964** | **72** | **88** | **85.77%** |

相较展开初版，漏检从 168 降至 88；相较长上下文版，从 186 降至 88。这是后续 IBO 能够工作的重要实证基础。

但它本身不是长尾分类终点：同一报告中 38 个尾类实例仅 9 个正确、16 个错类、13 个漏检（23.68%），而非尾类为 87.94%。这明确显示问题已从“看不见”转为“看见但常错分”。

### 3.3 对创新点的支持强度

- 强支持：你的方法为什么采用 D-FINE query / 候选区域作为后续证据载体。
- 强支持：不拉伸的循环展开对焊道结构保真和候选召回有价值。
- 不支持：不能把这一步当作正常参照、频率融合或尾类分布校准已经有效的证据。

## 4. 阶段 II：候选池、IBO 区域证据与召回保护

### 4.1 做了什么

冻结一阶段 D-FINE，不再改变主检测器。对每个预测框构造 IBO（内部 I、边界 B、外围 O）区域，并保留：

- D-FINE 原始类别与置信度；
- 框几何、tile 位置及环向映射；
- I/B/O 的颜色、亮度、梯度、纹理和深层/统计空间特征；
- I/B/O Haar 多频带、DCT、边缘等局部频率统计；
- I→B、B→O 的过渡差异特征。

也就是说，实际实现已经具备“内部—边界—周边”局部证据，但目前是候选后处理特征，不是论文原设想的端到端 query 注入层。

### 4.2 为什么同时保留 0.40 / 0.25 / 0.15 三个候选池

| 集合 | 阈值 | 验证 IBO crop 数 | 非钢帽 GT 覆盖 | 用途 |
|---|---:|---:|---:|---|
| 高置信 | 0.40 | 2,982 | 972 / 1,124 = 86.48% | 干净的基线/展示 |
| 主候选 | 0.25 | 7,818 | 1,040 / 1,124 = 92.53% | IBO 主输入 |
| 召回保护 | 0.15 | 19,780 | 1,079 / 1,124 = 96.00% | 防止低分尾类过早丢弃 |

训练侧相应候选数为 11,093 / 25,764 / 58,010。阈值从 0.40 降至 0.25 和 0.15 的意义不是让最终输出更多，而是把“低分但真实”的尾类和模糊缺陷留给第二阶段判断。低阈值候选必然也会带来大量背景与错类候选，这正是可靠性融合存在的原因。

### 4.3 IBO reliability 的已验证结果

使用 25,764 个训练候选、7,818 个验证候选训练 ExtraTrees 可靠性模型。输入包括 D-FINE 分数、几何、I/B/O 空间过渡、Haar 频率过渡及颜色/纹理/边缘/DCT 统计。候选级验证指标：AUROC 0.7980、AUPR 0.8506。

| 方法 | 阈值 | 正确 / 错误 / 漏检 | 实例有效覆盖率 | 含义 |
|---|---:|---:|---:|---|
| D-FINE 高置信 | 0.40 | 972 / 90 / 62 | 86.48% | 固定高阈值会丢失低分真缺陷 |
| IBO reliability（召回优先） | 0.15 | 1,040 / 57 / 27 | 92.53% | 保留真候选，同时少于基线的错类/漏检 |
| IBO reliability（整图更干净） | 0.65 | 958 / 91 / 75 | 85.23% | 图像级误报更少，但代价是漏检增加 |

这组结果证明“可靠性重评估 + 候选保护”可在召回优先的设定中把 972/90/62 改善为 1040/57/27。但它不是一个固定、普适的阈值结论：0.15 服务于二阶段候选保留，0.65 服务于最终展示/高精度筛选，两者不应混用。

### 4.4 纯尾类改善：当前最直接的长尾证据

在三类合并/烟类合并的特定审计协议下，定义纯尾类为小焊烟、焊坑、缺焊裂、焊缝蓝黑、焊灰色、焊高缝，共 33 个验证实例：

| 方法 | 正确 | 错误 | 漏检 | 纯尾类正确率 |
|---|---:|---:|---:|---:|
| D-FINE 高置信基线 | 5 | 21 | 7 | 15.15% |
| D-FINE + IBO reliability | 13 | 17 | 3 | 39.39% |

即正确实例 +8，漏检 -4，正确率 +24.24 个百分点。代表性变化：焊灰色 1/9 → 5/9，焊坑 0/2 → 2/2，小焊烟漏检 7 → 3。

这个结果可以支持“候选保护缓解固定高阈值压制尾类”的论点；不能支持“已解决所有尾类细分类”。例如缺焊裂、焊高缝各只有 1 个实例，焊缝蓝黑仍以错类为主。

## 5. 阶段 III：环向跨滑窗同类归并

### 5.1 为什么需要

循环重叠滑窗会让同一缺陷在相邻 tile 中出现多个框。若不归并：重复框使错类/误报统计变差，长条缺陷还可能被碎片化。归并在展开焊道的全局环向坐标完成，**只做同类合并**，不进行“跨类别多数投票”。

### 5.2 已验证结果

| 方法 | 候选/归并框数 | 正确 / 错误 / 漏检 | 实例有效覆盖率 |
|---|---:|---:|---:|
| 归并前 reliability ≥0.45 | 5,913 | 1,010 / 77 / 37 | 89.86% |
| 归并保护（同类，主 0.45 / 保护 0.25） | 1,573 | 1,042 / 60 / 22 | 92.70% |
| 同条件 class-vote 跨类归并 | 947 | 784 / 319 / 21 | 69.75% |

同类归并同时大幅减少冗余框并减少漏检；跨类别投票会破坏本来就脆弱的尾类标签，因此应明确排除。类别级例子：小焊烟 4/4/5 → 7/4/2，焊洞长 58/12/1 → 67/4/0。

### 5.3 写作边界

该结果是在验证集扫归并参数得到的开发结论。正式测试中应冻结“同类归并、主阈值 0.45、保护阈值 0.25、IoU 0.50”等设置，不能在测试集重新挑最优参数。

## 6. 阶段 IV：正常参照库、频率证据与可靠性融合

### 6.1 实现了什么

正常参照库从**训练集无标注 strip 区域**抽取 6,000 个样本构成，避免直接使用验证图的正常外观。每个 IBO 候选相对于正常焊道参考计算空间/纹理距离与频率异常证据，并和 D-FINE / IBO 可靠性共同用于候选级评分。

候选 group 层的正常参照—频率证据—可靠性融合 v2 达到：AUROC 0.8898、AUPR 0.8625、Brier 0.3055。说明这些特征对“候选是否可靠”有可分性，也说明其概率校准仍不理想（Brier 不低）。

### 6.2 必须如实报告的负结果

同一组输入候选（已归并的 1,573 个 group）上，直接按 v2 分数增大阈值，结果没有超过不额外过滤的输入：

| 回投方法 | 正确 / 错误 / 漏检 | 实例有效覆盖率 |
|---|---:|---:|
| 输入归并候选，不做 v2 截断 | 1,042 / 60 / 22 | 92.70% |
| v2 score ≥0.10 | 1,041 / 61 / 22 | 92.62% |
| v2 score ≥0.50 | 1,031 / 67 / 26 | 91.73% |
| v2 score ≥0.85 | 958 / 110 / 56 | 85.23% |

解释是：当前融合器能为候选排序，但用统一阈值去删候选会优先删掉低置信真尾类，从而抵消它的判别优势。由此不能写“正常参照 + 频率证据已使最终精度由 92.70% 再提升”。

### 6.3 与论文创新点的对应关系

| 原始创新主张 | 当前实际证据 | 当前结论 |
|---|---|---|
| 正常参照空间过渡结构 | I/B/O 颜色、纹理、边缘/过渡特征已进入候选可靠性模型 | 已实现为候选级证据；独立实例级增益尚未验证 |
| 正常参照局部频率校正 | Haar/DCT/局部频带统计、训练集正常库、候选 AUROC/AUPR | 已显示可分性；统一阈值未转化为最终增益 |
| 可靠性引导双域融合 | ExtraTrees 对空间/频率/检测分数联合评分 | 已验证候选重评估有效；并非论文公式中的端到端不确定性 Softmax 融合 |
| 覆盖度分布校准 DSC | 尚无与公式等价的类别—位置协方差校准训练和测试 | 尚未实现；不要写为已完成贡献 |

要让这部分成为论文强创新，下一轮必须做“尾类允许低检测分数、但必须同时满足强正常参照/频率证据”的**类别/不确定性条件决策**，而不是对所有类别一把尺阈值截断。

## 7. 阶段 V：混淆类对比纠错

### 7.1 问题定位

焊灰色是典型的“少数类被相似多数类吸收”：D-FINE 与可靠性模块往往能判断该位置存在异常，却把它归入缺焊长塌/蓝黑等长条主导类。为此，二阶段纠错器仅在高频混淆簇内比较候选与类原型/局部区域特征，不在全类别空间中粗暴重分类。

其输入来自候选 crop 的局部视觉/纹理和频率、正常参照偏离、候选原始分数、与“焊灰色”和“缺焊长塌族”原型的相对距离；仅在置信条件满足时改类。

### 7.2 统一 A0--A5 消融：必须作为主表的真实结论

2026-09-12 的统一消融使用原始验证 evidence、不含从训练集抽出的长焊高 holdout；规则为 20% GT 覆盖、IoU 0.50 错类辅助，烟类和缺焊长塌类按既定家族合并。

| 方法 | 最优开发阈值 | 总体正确 / 错误 / 漏检 | 总体正确率 | 重点尾类 | 焊灰色 | 缺焊长塌合并 |
|---|---:|---:|---:|---:|---:|---:|
| A0 D-FINE 原始分数 | 0.25 | 1051 / 44 / 27 | 93.67% | 81.56% | 5/9 = 55.56% | 228/232 = 98.28% |
| A1 A0 + IBO 空间/组证据 | 0.30 | 1049 / 46 / 27 | 93.49% | 80.85% | 55.56% | 98.28% |
| A2 A1 + 正常参照 | 0.35 | 1049 / 46 / 27 | 93.49% | 80.85% | 55.56% | 98.28% |
| A3 A1 + 频率证据 | 0.10 | 1050 / 45 / 27 | 93.58% | 81.56% | 55.56% | 98.28% |
| A4 A1 + 正常参照 + 频率 | 0.15 | 1050 / 45 / 27 | 93.58% | 81.56% | 55.56% | 98.28% |
| A5 A4 + 混淆类纠错 | 0.15 | 1044 / 51 / 27 | 93.05% | **83.69%** | **8/9 = 88.89%** | 219/232 = 94.40% |

正确解读：

- A1--A4 没有胜过 A0，故**目前不能宣称**正常参照或频率分支的独立最终收益。
- A5 使焊灰色多正确 3 个（5→8），错类由 4 降至 1；但长焊高塌合并类少正确 9 个（228→219），总体少正确 7 个。这是定向长尾校准的真实代价。
- 因此论文中的主要评价不应只给全体正确率，还必须给 Tail AP/尾类宏平均、尾类漏检、关键混淆对的双向混淆矩阵，以及头类性能变化。

## 8. “方法怎样一步一步缓解长尾”——论文叙事版本

### 8.1 可成立的因果链

1. **几何保真与循环上下文**：保持焊道细纹理比例、消除首尾断裂，减少“真实缺陷根本没有 query”的漏检。
2. **低分候选保护**：尾类常有弱响应，不以头类阈值直接淘汰；0.25/0.15 候选池把它们交给二阶段。
3. **IBO 可靠性重评估**：结合候选局部内部—边界—外围证据，筛掉部分背景/错类候选，同时保留低置信真候选。
4. **环向同类归并**：把同一缺陷跨重叠窗的多个预测统一，防止碎片化和重复框进一步污染尾类统计。
5. **正常参照与频率证据**：从“绝对亮/高频”转为“相对相同焊道条件下正常纹理的偏离”。当前已验证其候选可分性，尚待改为条件化决策来获取最终增益。
6. **混淆类对比纠错**：只在“尾类 vs 最易吸收它的头类”之间重判，直接攻击长尾最典型的类别吸收错误。

### 8.2 不应这样写

- 不要写“所有模块均提升总体精度”。A1--A4 的统一消融不支持这句话。
- 不要把 92.70%、93.67%、93.05%放在同一张表中比较而不写清候选池、阈值和家族匹配口径。
- 不要把测试集未做的阈值扫描结果称为“测试准确率”。
- 不要把候选级 AUROC/AUPR 误写成最终检测 mAP 提升。
- 不要把尚未实施的 DSC 协方差分布校准写成已完成模块。

## 9. 正式论文还必须补做的实验

### 9.1 先把实验协议冻结

1. 重新确认 train / val / test 为源图像级不重叠；测试集从未用于阈值、归并参数、尾类原型或纠错器选择。
2. 正常参照库、类原型、可靠性模型仅用训练集构建。
3. 在 validation 上一次性选择：D-FINE 置信阈值、IBO 阈值、归并参数、尾类纠错启用阈值。
4. 将所有参数写进 YAML/JSON，冻结后只在 test 执行一次。
5. 每种方法至少报告 3 个随机种子；尾类极少时同时做 bootstrap 95% CI 或源图像级 bootstrap。

### 9.2 最小但足够的消融表

| 编号 | 方法 | 要证明什么 |
|---|---|---|
| B0 | D-FINE-S，原始/普通输入 | 原始检测基线 |
| B1 | D-FINE-S + 150 px 不拉伸循环滑窗 | 几何保真候选生成 |
| B2 | B1 + IBO reliability + 同类归并 | 候选保护与去冗余 |
| B3 | B2 + 正常参照空间证据 | 正常参照的独立贡献 |
| B4 | B2 + 局部频率证据 | 频率证据的独立贡献 |
| B5 | B2 + 正常参照 + 频率可靠性融合 | 双域互补是否成立 |
| B6 | B5 + 混淆类对比纠错 | 尾类被相似头类吸收是否缓解 |

正式表的阈值不能再由每一行在测试集“各自找最好”得到。全部用验证集选定。对于 B3--B5，若仍无独立增益，应诚实收缩论文贡献，集中到“候选可靠性 + 混淆纠错”，不要强行维持双域融合的大主张。

### 9.3 最终指标表

- 检测：mAP、AP50、AP75、AR100；每类 AP；Head / Medium / Tail 的 macro AP；Tail AP。
- 工业实例：正确/错类/漏检；尾类正确率；尾类漏检率；关键混淆对的错分数。
- 校准：ECE、Brier、NLL（若确实做置信度/分布校准）。
- 工程：参数量、FLOPs、单图或单环平均推理时间。
- 显著性：源图像级 bootstrap CI；至少三个种子的均值±标准差。

## 10. 回答问题二：是否必须用别人的方法跑我们的数据集？

**需要。** 你已经把自己的方法迁移到公开数据集，这能说明可迁移性；但不能替代“外部方法在你的焊接长尾数据上与我们方法对比”。论文审稿人会追问：提升是否只是来自 150 px 展开、数据处理或 D-FINE，而不是你的长尾机制？把兼容的外部方法放到同一焊接数据、同一划分、同一预处理下，才是最有说服力的回答。

但不是把所有论文原封不动搬过来。只应复现**有公开代码、适用于目标检测、无需额外外部语义数据也能公平运行**的方法；分类专用、依赖 ImageNet-LVIS 外部标注或改变任务定义的方法，应在相关工作中讨论，不能伪装为原方法的公平数值对比。

### 10.1 建议的对比矩阵

| 类型 | 建议方法 | 在你的数据上的作用 | 是否应优先 |
|---|---|---|---|
| 同架构无长尾 | D-FINE-S | 核心基础线；已有 | 必须 |
| 常见一阶段检测器 | YOLO11n | 验证 D-FINE 是否只是架构优势 | 必须 |
| Transformer 检测器 | RT-DETRv2 | 验证不是只对一个检测范式有效 | 必须 |
| 长尾损失基线 | Focal / Class-Balanced Focal | 最低成本、清晰的重加权对照 | 必须 |
| 长尾检测损失 | EQLv2（或 Seesaw，二选一） | 对比“只改类别不平衡损失”与我们的候选证据策略 | 必须 |
| 后验校准 | NorCal / 同类可复现的 calibration baseline | 对比“只改分数校准”与正常参照/纠错 | 建议 |
| 文献中的完整系统 | LoHi-WELD 等公开且可运行的检测方法 | 同领域系统性比较；需保持其原训练规范 | 代码与任务匹配时做 |
| SimLTD、LOS、RichSem 等 | 许多依赖不同检测框架、训练阶段或外部语义数据 | 可以做“适配实现”，但必须标成 adapted baseline，不可称原方法原样复现 | 不作为第一优先 |

### 10.2 公平运行规则

对 YOLO11n、RT-DETRv2、D-FINE-S+Focal/EQLv2 和我们的方法：

1. 使用完全相同的**源图像 train/val/test 划分**和类别字典；
2. 为比较长尾策略，先统一使用同一份 150 px、不拉伸、循环滑窗数据；否则预处理收益和长尾方法收益混在一起；
3. 除架构必需的输入尺寸/学习率调整外，匹配总训练步数、数据增强、早停/最佳 checkpoint 选择规则；
4. 不允许外部方法用测试集挑阈值；
5. 同时报标准 COCO 指标与本项目实例审计指标；
6. 若外部方法不能处理环形展开，提供其“原图输入”附表，但主长尾策略对比仍应在同一数据表示下完成。

### 10.3 最小可发表的执行顺序

1. 先把本方法 B0--B6 在独立测试协议上补齐；
2. 跑 YOLO11n、RT-DETRv2 两个架构基线；
3. 在 D-FINE-S 上实现 Focal/CB-Focal 与 EQLv2（至少一个强长尾损失）；
4. 再选择一个后验校准基线；
5. 最后做本方法完整消融与三种子重复。

这样能回答四个不同问题：架构是否更好、简单重加权是否足够、普通校准是否足够、你的“候选可靠性 + 正常参照/频率 + 混淆纠错”是否有额外价值。

## 11. 可直接放进论文的当前阶段性结论

> 在自建圆环焊道缺陷数据上，采用源图像级划分和 150 px 无拉伸循环展开后，D-FINE-S 的实例级漏检数由展开初版的 168 个降至 88 个，说明几何保真与环向连续上下文能够改善缺陷候选覆盖。进一步地，在低置信候选保护与 IBO 可靠性重评估下，纯尾类的实例级正确率在相应高置信基线比较中由 15.15% 提升至 39.39%，表明候选可靠性建模可缓解固定阈值对低分尾类的过早剔除。跨滑窗同类归并进一步将候选数由 5,913 压缩至 1,573，并将实例有效覆盖率由 89.86% 提升至 92.70%。对于焊灰色与缺焊长塌族的高频混淆，定向对比纠错将焊灰色正确率由 55.56% 提升至 88.89%，但伴随总体正确率由 93.58% 降至 93.05%，显示该机制属于受控的头尾性能权衡。正常参照与局部频率特征在候选级可靠性判别中已显示可分性，但其独立的最终检测增益仍需在冻结阈值的独立测试集上验证。
