# RichSem/LVIS 长尾检测实验方案

## 1. 实验目的与边界

本方案用于在 LVIS v1 上评估“D-FINE + IBO 区域证据 + 局部频率证据 + 可靠性融合 + 混淆类对比纠错”的长尾检测能力，并建立与 RichSem 的可解释、公平的对照。

RichSem 是长尾目标检测方法，不是独立数据集。其标准设置由 LVIS v1 和可选的 ImageNet-LVIS 外部图像级标签构成。为避免把外部数据收益误判为方法收益，实验分为两个彼此独立的轨道：

| 轨道 | 数据条件 | 回答的问题 | 结果用途 |
|---|---|---|---|
| A：核心方法 | 仅 LVIS v1 | 我们的方法在不使用额外图像级标签时，是否改善长尾检测与混淆纠错？ | 论文主结果 |
| B：数据对齐 | LVIS v1 + ImageNet-LVIS | 在与 RichSem 相同的外部数据条件下，我们的方案表现如何？ | 与 RichSem 的公平补充对照 |

当前正在运行的 `pilot10k` 训练仅用于验证流程、资源消耗和模块接口，不能作为正式论文中的 LVIS 对比结果。

## 2. 研究问题与预注册假设

### RQ1：长尾性能

在 LVIS v1 的极端类别不均衡下，完整模型能否在保持常见类性能基本稳定的条件下，提高 rare 类的 `AP_r`？

### RQ2：双域证据的有效性

IBO 的内部—边界—外部区域特征与局部频带变化，是否能提高候选框的可信度判别，减少漏检候选？

### RQ3：混淆类纠错的有效性

以 D-FINE detection-query embedding 进行局部混淆类重排序，是否能减少高频混淆簇中的错类预测，而不显著伤害头类？

### RQ4：外部弱监督的可比性

在使用与 RichSem 相同 ImageNet-LVIS 图像级标签时，弱语义监督是否为模型带来额外收益？该收益必须与核心方法收益分开报告。

## 3. 数据与划分

### 3.1 轨道 A：LVIS-only

- 数据版本：LVIS v1.0 官方 `train` 与 `val` 标注。
- 训练：完整 `lvis_v1_train.json`，不使用 pilot 子集作为正式训练集。
- 验证：完整 `lvis_v1_val.json`，使用官方 LVIS evaluator。
- 类别分组：沿用 LVIS 定义的 rare (`AP_r`)、common (`AP_c`) 和 frequent (`AP_f`) 类别。
- 数据审计：训练前输出图像数、标注数、类别数、每类别实例数、r/c/f 类别数量及实例比例；将审计 JSON 与图表固化到运行目录。

### 3.2 轨道 B：RichSem 数据条件对齐

- 检测数据：与轨道 A 相同的 LVIS v1 train/val。
- 外部数据：RichSem 官方提供或其 README 指向的 ImageNet-LVIS 图像清单。
- 标签约束：ImageNet-LVIS 仅有图像级语义标签，不得被转换或伪造为边界框标注。
- 数据去重：检查 ImageNet-LVIS 与 LVIS val 的 image ID、文件名及近重复图像；发现重叠时从外部训练数据中排除。
- 报告：必须列出外部图像数量、映射至 LVIS 的类别数、每个 r/c/f 组的外部样本覆盖率。

## 4. 预处理与训练公平性

### 4.1 统一输入策略

- 检测器：D-FINE-S（HGNetv2-B0）。
- 输入：`ResizeMaxPad(640, 640)`，保持长宽比，padding 填充；不做拉伸。
- 不使用圆形焊道 ROI、极坐标展开或环向位置 `theta`。
- 不使用 150 px 循环滑窗。该滑窗是面向长焊道高分辨率图像的采样策略，LVIS 自然图像使用它会改变有效视野，不能和 RichSem 的全图检测设置公平比较。
- 随机增强：随机水平翻转和颜色扰动；其开关及概率写入配置文件。

### 4.2 优化设置

- 在所有 A 轨道消融中固定模型、数据划分、输入尺寸、batch size、优化器、随机种子和训练轮数。
- 正式运行使用 3 个随机种子；主表报告均值 ± 标准差。
- checkpoint 选择仅依据验证集 `AP_r` 最大化，同时约束 `AP_f >= AP_f(base) - delta`；默认 `delta=0.5` 个百分点，最终阈值写入运行配置。
- 置信度阈值仅用于候选级诊断；官方 AP 使用全部预测分数并由 LVIS evaluator 排序计算，不能以固定阈值代替。

### 4.3 RichSem 对齐说明

RichSem 的公开主结果使用不同的检测器和外部 ImageNet-LVIS 数据。因此绝对 AP 只能作为参考，不可写为“同模型直接胜负”。正式比较表必须同时注明：骨干、检测器、外部数据、图像尺度、训练 epoch、GPU 数量与评价版本。

## 5. 方法实现映射

### 5.1 D-FINE 基线

输入图像经过 D-FINE-S，保留每个 detection query 的分类 logits、预测框、query embedding 和多尺度特征。

### 5.2 IBO 区域证据

对每个候选框构造三个区域：内部 `I`、边界环 `B`、外部上下文 `O`。提取颜色/亮度、梯度、深层空间特征和局部频带能量，构成：

`E_s = [T_B^s - T_I^s, T_O^s - T_B^s]`

`E_f = [log(A_B) - log(A_I), log(A_O) - log(A_B)]`

LVIS 中不能宣称“正常焊缝参照”。这里使用的参照名称统一为“局部上下文参照”：候选外环及语义/尺度相近候选的稳健统计量。该设置仅测试区域证据的可迁移性。

### 5.3 局部频率证据

在 `I/B/O` 上计算小波或可学习频带分解的低、中、高频响应以及方向响应。不得使用整图 FFT 的全局高频值作为候选频率特征。

### 5.4 可靠性融合

空间域与频率域分别输出不确定性与异常强度，以可靠性权重融合：

`omega_s, omega_f = Softmax(-u_s + xi*SNR_s, -u_f + xi*SNR_f)`。

输出应包括每候选的 `omega_s`、`omega_f`、可靠性分数和拒绝/保留决策，以便后续诊断。

### 5.5 混淆类对比纠错

使用 D-FINE query embedding 构建局部混淆簇，并仅在原模型的 top-k 候选类别及已验证混淆簇内重排序。该模块属于论文的“混淆类对比纠错”，不是为 LVIS 单独增加的功能。裁剪图像视觉统计仅作为可选消融，不能取代 query embedding 主实现。

## 6. 实验组与消融

轨道 A 的每组使用相同 D-FINE-S 主干、训练数据和训练预算。

| 编号 | 方法 | 用途 |
|---|---|---|
| A0 | D-FINE-S | 强基线 |
| A1 | A0 + IBO 空间区域证据 | 验证内部—边界—外部空间过渡 |
| A2 | A0 + IBO 频率区域证据 | 验证局部频带过渡 |
| A3 | A0 + 空间/频率固定融合 | 排除“仅仅多一个分支”的解释 |
| A4 | A0 + 可靠性融合 | 验证动态信任机制 |
| A5 | A0 + query 混淆类纠错 | 验证分类层纠错 |
| A6 | A0 + IBO + 频率 + 可靠性融合 + query 纠错 | 完整模型 |

轨道 B 单列：

| 编号 | 方法 | 外部数据 | 解释 |
|---|---|---|---|
| B0 | D-FINE-S | ImageNet-LVIS | 外部数据基线 |
| B1 | A6 + 弱语义训练分支 | ImageNet-LVIS | 我们方法在等数据条件下的增强版本 |
| B2 | RichSem 公开结果/可复现结果 | ImageNet-LVIS | 文献或复现参照 |

弱语义训练分支只允许使用图像级标签产生训练损失，在推理时删除。B1 必须作为“外部弱监督扩展”单列，不能覆盖 A6 的核心方法结论。

## 7. 评价指标

### 7.1 官方主指标

- `AP_box`：LVIS 官方边界框 mAP。
- `AP_r`、`AP_c`、`AP_f`：rare/common/frequent 类别 AP。
- `AP50`、`AP75`：定位质量。
- `AP_s`、`AP_m`、`AP_l`：目标尺度性能。
- `AR@1`、`AR@10`、`AR@100`：候选召回能力。

所有官方结果由同一版本 LVIS evaluator 生成，并保存原始 JSON 预测文件。

### 7.2 论文方法诊断指标

| 指标 | 定义 | 用途 |
|---|---|---|
| Candidate Recall | IoU 匹配后存在正确类别候选的比例 | 判断是否减少漏检 |
| Wrong-class Rate | 已定位候选中类别错误的比例 | 判断是否减少错选 |
| Pairwise Confusion Reduction | 高频混淆类别对的错误变化 | 验证 query 纠错 |
| Reliability AUROC/AUPR | 可靠性分数区分正确/错误候选的能力 | 验证可靠性融合 |
| Brier / ECE | 置信度校准质量 | 验证分数可信度 |
| Spatial/Frequency Weight Profile | `omega_s/omega_f` 按 r/c/f 与尺度分组的分布 | 检查融合是否退化为固定比例 |

### 7.3 结论判据

- 若 `AP_r` 上升且 `AP_f` 下降不超过预注册的 `delta`，支持长尾改善假设。
- 若 Candidate Recall 上升但 Wrong-class Rate 也上升，必须报告该权衡，不能仅报告召回收益。
- 若 A4 优于 A3，才可主张可靠性动态融合优于固定融合。
- 若 A5/A6 降低高频混淆对错误，同时不降低总 `AP_box`，才可主张混淆类对比纠错有效。
- LVIS 的局部上下文参照结果不能替代焊接数据集上的“正常焊缝参照”证明。

## 8. 执行顺序与产物

1. **数据审计**：生成 `dataset_audit.json`、类别长尾分布图和外部数据重叠报告。
2. **A0 正式基线**：完整 LVIS 训练，输出 best/last checkpoint、原始预测 JSON 和官方评价 JSON。
3. **候选导出**：从 A0 导出 IBO 所需的 query、框、logits 和区域特征索引。
4. **A1--A5 单模块消融**：固定训练/验证协议并保存全部运行配置。
5. **A6 完整模型**：按预注册 checkpoint 选择规则选取模型，生成主表和诊断表。
6. **错误分析**：按 r/c/f、尺度、典型混淆对输出定性样例及失败案例。
7. **B0--B2 外部数据对齐**：仅在 A 轨道完成后开展，单独生成比较表。
8. **重复与汇总**：关键组 A0、A4、A5、A6 跑 3 个种子，汇总均值、标准差、运行时和显存占用。

每个运行目录必须保留：完整 YAML、git commit（若适用）、随机种子、数据清单 hash、stdout/stderr、checkpoint、预测 JSON、官方指标 JSON 与诊断 CSV。

## 10. 论文中的表述边界

可以表述：

> 在 LVIS 上，区域空间—频率证据、可靠性融合与 query 级混淆纠错表现出对长尾检测的可迁移性。

不应表述：

> LVIS 实验证明了面向焊缝的正常参照机制。

焊接实验负责验证正常焊缝参照、反光抑制与焊道结构先验；LVIS 实验负责验证长尾类别、候选可靠性和混淆纠错的通用性。
