## 2. 统一比较原则

### 2.1 自有焊道协议

- 输入几何：圆环焊缝展开为周期焊缝条带；主比较使用无拉伸的 `1024 × 160`（150-px 有效焊缝高度）输入或其对应 D-FINE 周期切片。
- 训练/验证：使用既定训练、验证划分；随机种子为 0。
- 统一审计：对 1,122 个源实例进行候选级 `correct / wrong-class / missed`（C/W/M）审计；匹配 IoU = 0.50，部分覆盖阈值 = 0.20，碎片覆盖阈值 = 0.50。
- 类别处理：训练保留原始 23 个类别 ID；审计时移除非研究类别，并按既定规则合并烟类与缺焊长塌类。因此审计汇总与训练标签空间不混淆。
- 报告指标：All C/N、Tail C/N、Gray-weld C/W/M、Collapse-family C/N，以及每类 C/W/M；`C/N = correct / annotated instances`。

### 2.2 LVIS pilot10k 协议

- 数据：固定 LVIS-v1 pilot 训练标注 `lvis_v1_train_dfine_smoke.json` 与验证标注 `lvis_v1_val_dfine_smoke.json`；图像根目录为 `public_datasets/LVIS/images`。
- 输入：保持长宽比，最大画布为 `640 × 640`，用 padding 补齐，不做各向异性拉伸。
- 指标：LVIS API 的 AP、AP50、AP75、APr、APc、APf、AR@300；候选级审计（若有）与全预测排序 AP 分开报告，不能互相替代。
- 公平性边界：D-FINE-S/FRACAL 使用冻结的 100-epoch D-FINE-S 候选生成器；ROG 与 SimLTD 是独立检测器迁移，使用相同的 pilot 数据、640 输入、种子和 LVIS API，但不共享网络结构或训练预算。

## 3. 各实验方案与实际参数

### 3.1 SimLTD-style D-FINE-S 焊道统一复评（已完成）

**目的。** 将 SimLTD 的“头类训练—尾类调优—分类头融合”思想迁移到相同的 D-FINE-S 焊道检测器，用作长尾训练策略对照；它不是官方 SimLTD 代码的逐项复现。

**模型与训练。**

| 阶段 | 配置 | 训练对象 | Epoch | 学习率/调度 | 关键操作 |
|---|---|---|---:|---|---|
| Stage 1 | `dfine_hgnetv2_s_zhwk_simltd_style_stage1.yml` | 头类视图 | 20 | 继承 D-FINE-S；milestone 14, 18；gamma 0.1 | 训练头类分类头 |
| Stage 2 | `dfine_hgnetv2_s_zhwk_simltd_style_stage2.yml` | 尾类视图 | 6 | AdamW, lr `1e-5`；milestone 4, 5；gamma 0.1 | `--tuning --head-only` 尾类调优 |
| Stage 3 | `dfine_hgnetv2_s_zhwk_simltd_style_stage3.yml` | 联合视图 | 6 | AdamW, lr `1e-5`；milestone 4, 5；gamma 0.1 | 融合头/尾分类头后联合校准 |

- D-FINE 工作目录：`third_party/D-FINE`；训练入口：`scripts/train_dfine_simltd_style_stage.py`。
- Stage 2 尾类 ID：`2, 8, 10, 11, 17, 18, 19, 20, 22`；融合产物为 `fused_head_tail.pth`。
- 运行目录：`zhwk_runs/simltd_style_dfine_s_zhwk_150px_32ep_20260920_seed0`。
- 最终模型：`stage3_joint_k30/last.pth`；统一审计目录：`stage3_joint_k30/unified_strict_audit_1122_t025_20260923`。

### 3.2 FRACAL 焊道统一审计（已完成）

**目的。** 在冻结 D-FINE-S 检测器上运行 FRACAL 的频率/分形校准头，检验其对自有长尾焊道类别的后处理作用；不更新检测器权重。

**实际参数。**

| 项目 | 设置 |
|---|---|
| 基础模型 | D-FINE-S，`best_stg1.pth`，周期焊缝条带训练版本 |
| 输入 | 无拉伸 `160 × 1024` |
| 设备/批量 | CUDA，batch size 4 |
| 原始候选阈值 | 0.25 |
| FRACAL 最终阈值 | 0.056（预算匹配选择） |
| 每图候选上限 | 300 |
| 分形指数 | 2.0 |
| 分形网格上限 | 32 |
| 校准公式 | `sigmoid(z) × sigmoid(z + frequency_adjustment + fractal_adjustment)` |
| 审计 | IoU 0.50；partial coverage 0.20；fragmented coverage 0.50 |
| 汇总范围 | 13 个分组合并类别，1,122 个源验证实例，另含 4 个长焊高诊断保留实例 |

- 脚本：`scripts/run_dfine_fracal_weld.py`。

### 3.4 官方 SimLTD 的 LVIS fast pilot 重实现（进行中）

**目的。** 在 LVIS pilot10k 上保留官方 SimLTD 的 head/tail/combined 三阶段思想，形成与 D-FINE-S、FRACAL、ROG 可比较的独立检测器对照。

**重要边界。** 这是一项 *fast pilot reimplementation*，不是官方全 LVIS 配方复现：采用缩短的 20/6/6 数据遍历预算、固定 640 输入，且由于 Deformable-DETR 为 bbox-only 检测器，移除了官方 `CopyPaste` 所依赖的分割 mask 读取。

| 阶段 | 配置 | 训练预算 | 物理 batch / 有效 batch | 学习率 | 输入与增强 |
|---|---|---:|---|---|---|
| Head866 | `simltd_r50_lvis_pilot10k_head_fast640_20ep.py` | 100,000 iter（20 pass） | 2 / 4（累积 2） | `2e-4` | 640 keep-ratio + pad；bbox-only；flip、RandAugment |
| Tail337 | `simltd_r50_lvis_pilot10k_tail_fast640_6ep.py` | 30,000 iter（6 pass） | 2 / 2 | `1e-4` | 同上 |
| Finetune1203 | `simltd_r50_lvis_pilot10k_finetune_fast640_6ep.py` | 30,000 iter（6 pass） | 2 / 4（累积 2） | `1e-5` | 同上 |

- 三阶段均：seed 0、AMP、验证 batch 1、模型权重 checkpoint（不保存 optimizer/scheduler）、`max_keep_ckpts=2`。
- Head 阶段里程碑：88,889 / 100,000 iteration；finetune 里程碑：26,250 / 30,000 iteration。
- Stage 1 当前运行目录：`zhwk_runs/simltd_official_lvis_pilot_20260924/fast640_32ep/stage1_head866_20ep`。
- Stage 1 完成后，必须用官方 `checkpoint_surgery.py` 生成并核验 head-reset 产物，才可启动 Tail；Tail 完成后同理生成 head-tail combined-reset 产物，才可启动 Finetune。
- 代码：`third_party/simltd_official_snapshot/simltd-main`；环境：`simltd_pilot_py310`。

### 3.5 ROG 自有焊道迁移（已完成）

**目的。** 使用官方 ROG 的 `ROGShared2FCBBoxHead` 与 GAP ranking loss，在同一焊缝条带数据和统一审计协议下构建架构不同的长尾对照。

**实际参数。**

| 项目 | 设置 |
|---|---|
| 检测器 | Faster R-CNN R50-FPN + `ROGShared2FCBBoxHead` |
| 类别数 | 原生 23 类；只在审计后合并/排除指定类别 |
| 输入 | 1024 × 160，保持几何比例；divisor-32 padding |
| 训练集 | `instances_train_diverse_neg0p5_ascii.json` |
| 验证集 | `instances_val.json` |
| 采样 | ClassBalancedDataset，`oversample_thr=1e-3` |
| batch / workers | 4 / 4 |
| 优化器 | SGD，lr 0.005，momentum 0.9，weight decay `1e-4` |
| 调度 | 32 epochs；linear warmup 500 iter；step at epoch 21, 29 |
| 随机性 | seed 0，非 deterministic |
| 推理候选 | `score_thr=1e-4`，每图至多 300；统一审计时 `t=0.25` |

- 配置：`rog_configs/rog_faster_rcnn_r50_zhwk_150px_32ep.py`。
- 最终 checkpoint：`epoch_32.pth`。
- 统一审计目录：`uniform_strict_audit_1122_t025_20260926`。

## 4. 写入论文时的措辞边界

1. **SimLTD-style D-FINE-S**：写作“SimLTD-inspired three-stage D-FINE-S baseline”，不要称作官方 SimLTD 重现。
2. **FRACAL**：是冻结检测器后的分数校准/重排序，不应与重新训练的检测器直接以训练成本作等价比较。
3. **ROG**：保留 ROG 分类头与 ranking loss，但为了 bbox-only 数据使用 Faster R-CNN；写作“controlled ROG transfer baseline”。
4. **SimLTD LVIS fast pilot**：在完成后写作“official SimLTD codebase, fast pilot protocol”；必须披露 20/6/6 预算、640 输入、移除 CopyPaste/mask 路径，不能称为完整官方 LVIS 结果。
5. LVIS API AP 与候选级 C/W/M 审计必须分别报告，不能把候选审计的提升解释成完整 AP 提升。
