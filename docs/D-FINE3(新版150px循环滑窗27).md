# 新版 150px 循环滑窗 D-FINE 模型评价报告

## 1. 结论先行

本次模型是目前几版 D-FINE 里最==适合作为后续 IBO / 正常参照证据学习==流程入口的一版。

它的主要改进不是网络结构本身，而是输入形态和训练数据策略更合理：不再把 150px 高度的焊道强行拉伸到 256px，而是保持焊道展开后的原始径向比例，用 `1024 × 150` 的长条滑窗训练；为了适配 D-FINE 的特征步长，图像只向下补边到 `1024 × 160`，不缩放缺陷框。同时，训练集删减了大量高度重复的空白负样本，只保留较多样的空白片段。

按当前实例级统计规则，即“正确 / 错类 / 漏检”三类，并且同类碎片化或部分覆盖只要覆盖率达到 20% 以上就算识别正确，在验证集不含钢帽的 1,124 个缺陷实例上：

| 模型 | 正确 | 错类 | 漏检 | 总实例 | 准确率 |
|---|---:|---:|---:|---:|---:|
| 圆环版 | 864 | 53 | 207 | 1,124 | 76.87% |
| 展开初版 | 893 | 63 | 168 | 1,124 | 79.45% |
| 长上下文版 | 884 | 54 | 186 | 1,124 | 78.65% |
| 新版 150px 循环滑窗 | 964 | 72 | 88 | 1,124 | 85.77% |

最关键的变化是：新版把漏检从展开初版的 168 个、长上下文版的 186 个，降到了 88 个。也就是说，它更像一个“尽量把可疑区域先捞出来”的候选框生成器。这对后面的 IBO、频率证据、可靠性融合是有利的。

==但它还没有真正解决尾类问题==。尾类整体只有 38 个实例，新版正确 9 个，准确率 23.68%；错类 16 个，漏检 13 个。也就是说，新版更会“看见一些尾类痕迹”，但经常把它们认成相近类别。==因此后续不能只依赖 D-FINE 的类别输出==，而应该把 D-FINE 当成候选区域生成器，再用正常参照、频率证据和分布校准去二次判断。

## 3. 数据构建方式

### 3.1 焊道展开与滑窗

本版采用“ROI 找圆形焊道 → 展开成直线焊道 → 循环滑窗切片”的路线。

| 项目 | 设置 |
|---|---|
| 展开焊道高度 | 150px |
| 滑窗宽度 | 1024px |
| 滑窗高度 | 150px |
| 训练实际输入 | 1024 × 160，底部补边 10px |
| stride | 768px |
| 重叠宽度 | 256px |
| 首尾连续 | 使用循环展开 / cyclic tiles，避免焊道首尾断裂 |
| 标注保留阈值 | `min-visible = 0.5` |

这里的核心点是：缺陷在径向方向不再被拉伸。上一版把 150px 高的焊道拉到更高，会让焊高纹、缺焊蓝黑、长焊高塌这类细长纹理发生形变；新版只补边，不重采样，缺陷几何形态更接近真实图像。

### 3.2 训练集负样本处理

训练集构建后，原始切片中空白片段过多，因此使用 MD5 和感知哈希去除大量重复空白负样本。

| 项目 | 数量 |
|---|---:|
| 原始训练源图像 | 3,099 |
| 原始训练标注实例 | 6,263 |
| 与焊道区域相交实例 | 4,710 |
| 已表示到展开切片中的实例 | 4,707 |
| 原始生成训练 tiles | 20,982 |
| 原始空白 tiles | 17,079 |
| 筛选后训练 tiles | 5,855 |
| 筛选后空白 tiles | 1,952 |
| 筛选后训练标注 | 6,855 |
| 空白片段占比 | 33.34% |

负样本筛选规则的作用是让模型不要被大量重复、几乎一样的正常焊道背景“淹没”。这一步对这版模型提升很明显：模型不再像上一版那样在验证图上大面积漏检，而是更愿意给出候选框。

## 6. 评价规则

本报告采用你后面确认过的三分类规则：

| 类别 | 含义 |
|---|---|
| 正确 | 模型在对应缺陷位置给出了同类别框；或同类别碎片化 / 部分覆盖框对人工标注的覆盖率达到 20% 以上 |
| 错类 | 检到了对应位置，但类别判断成其他缺陷类别；或同一缺陷同时出现明显错误类别竞争框 |
| 漏检 | 没有检测到；或同类覆盖不足 20%；或该人工标注没有被展开切片有效表示 |

统计口径：

- 主表不含钢帽。
- 置信度阈值为 0.40。
- 严格匹配 IoU 为 0.50。
- 对细长缺陷额外采用“20%覆盖即算候选有效”的宽松规则。
- 这里的准确率为 `正确 / 标注实例`，更接近“缺陷实例被有效召回为 query 的比例”，不是传统分类准确率。

## 9. 主要改进在哪里

### 9.1 对细长纹理类缺陷改善明显

新版对==焊高纹==提升最大：

- 圆环版：68.34%
- 展开初版：78.38%
- 长上下文版：82.24%
- 新版：93.82%

这说明“保持 150px 原始径向比例 + 1024 宽滑窗 + 首尾连续”确实更适合焊道纹理类缺陷。焊高纹这类缺陷不是一个孤立圆点，而是一段沿焊道方向延伸的纹理异常；展开以后，模型更容易在横向上下文里理解它。

### 9.2 ==漏检显著下降==

总漏检数量变化：

| 模型 | 漏检 |
|---|---:|
| 圆环版 | 207 |
| 展开初版 | 168 |
| 长上下文版 | 186 |
| 新版 | 88 |

这个变化很重要。因为后续 IBO 需要有 query，如果第一阶段完全不画框，后面就没有候选区域可分析。新版虽然错类略有增加，但漏检大幅下降，因此更适合作为第一阶段候选框生成器。

新版总错类为 72 个，高于：

- 圆环版：53 个
- 展开初版：63 个
- 长上下文版：54 个

这说明新版更积极地召回缺陷，但分类边界还不够干净。对后续研究来说，这反而提供了一个很好的切入点：D-FINE 负责产生候选位置，后续的频率证据、正常参照和分布校准负责修正类别与置信度。

### 10.3 部分类别仍存在类别混淆

比较突出的类别包括：

- 焊洞长：正确 54，错类 11。
- 长焊高塌：正确 100，错类 15。
- 焊灰色：正确 2，错类 5。
- 焊缝蓝黑：正确 1，错类 5。

这些类别的问题不完全是检测框问题，而是类别定义之间存在外观重叠。尤其是“颜色变化类”和“长条纹理类”，只靠目标检测网络的类别头很难稳定区分。

## 11. 对后续 IBO / 正常参照证据路线的意义

本模型可以进入下一步，但使用方式要明确。

推荐把新版 D-FINE 定位为：

> 缺陷候选 query 生成器，而不是最终缺陷判决器。

原因如下：

- 它的漏检已经明显下降，能给后续模块提供更多候选区域。
- 它对焊高纹、缺焊蓝黑、焊高烟、长焊高裂等主要类别已经有较高覆盖。
- 它的错类问题正好可以交给后续的正常参照、频率证据和可靠性融合去处理。
- 对尾类，不应该相信 D-FINE 的单一类别概率，而应该保留候选框，并在二阶段重新判断。

后续 IBO 构建建议：

1. 对 D-FINE 高置信框直接构建 IBO。
2. 对 D-FINE 低置信但位于焊道纹理异常区域的框也保留为候选 IBO。
3. 对长条类缺陷，将相邻或重叠的同类 / 相近类框做一维焊道方向合并，避免一个长缺陷被切成很多碎片。
4. 对尾类不要只用类别阈值过滤，否则会把本来就少的尾类再次过滤掉。
5. 对未被 D-FINE 框覆盖的焊道区域，可以补一个轻量的密集滑窗异常候选，用于防止完全没有 query。

## 12. 是否适合作为当前主线模型

我的判断：适合。

但它适合的是“进入下一阶段研究”的主线模型，不适合作为“最终检测模型”直接写结论。

如果论文主线是：

> 展开焊道上的长尾缺陷检测，先用检测器产生候选，再通过正常参照空间、频率证据学习、可靠性融合和分布校准提升长尾缺陷判别。

那么新版 150px 循环滑窗 D-FINE 是目前最合适的第一阶段模型。它把“没有 query”这个问题从 168 / 186 个漏检压到了 88 个，已经能支撑后续模块继续实验。

如果论文主线只写“D-FINE 单模型直接检测所有长尾焊接缺陷”，那这版还不够，因为尾类准确率只有 23.68%，不能证明长尾问题被解决。

## 13. 下一步建议

建议下一步不要继续盲目训练 D-FINE，而是进入“候选框后处理 + IBO 构建”的小实验。

优先级如下：

1. 固定新版 D-FINE 的 `best_stg1.pth` 作为候选生成器。
2. 在验证集上导出所有候选框，保留坐标、类别、置信度、tile 来源、映射回原图 / 展开焊道的位置。
3. 做一维焊道方向的框合并，专门处理长焊高塌、焊高纹、焊洞长、缺焊蓝黑这类长条缺陷。
4. 给每个候选框构建 IBO，包括局部缺陷块、邻域正常参照块、频域表示和可靠性指标。
5. 先用验证集做二阶段判断实验，不要直接碰测试集。

一个比较稳的实验推进方式是：

| 阶段 | 目标 | 判断标准 |
|---|---|---|
| A | 新版 D-FINE 候选框冻结 | 验证集候选覆盖稳定 |
| B | 框合并 / query 清洗 | 长条缺陷碎片减少，漏检不明显增加 |
| C | IBO 构建 | 每个候选框能找到对应正常参照区域 |
| D | 频率证据学习 | 错类样本能被二阶段特征拉开 |
| E | 可靠性融合与分布校准 | 尾类错类减少，置信度更可信 |
