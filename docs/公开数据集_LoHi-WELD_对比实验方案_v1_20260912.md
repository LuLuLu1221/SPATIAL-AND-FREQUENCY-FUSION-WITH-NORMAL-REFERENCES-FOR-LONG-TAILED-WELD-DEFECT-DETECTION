# 公开数据集 LoHi-WELD 对比实验方案 v1

## 1. 实验目的

在公开焊缝缺陷数据集上验证当前方法是否具有可迁移性，而不是只对我们自己的极柱圆环焊道数据有效。

核心问题：

1. D-FINE 基线在公开焊缝缺陷数据上能否达到合理检测性能；
2. 公开数据集是否也存在类别不均衡/长尾类被相似大类吸收的问题；
3. `D-FINE + IBO区域证据 + 正常参照空间 + 频率证据 + 混淆类纠错` 是否能在公开数据集上带来可解释提升；
4. 与原论文和公开方法比较时，评价指标、resize、学习率、阈值等关键参数保持一致。

## 2. 数据集选择

优先数据集：`LoHi-WELD`

选择原因：

- 表面焊道图像，和我们的任务同属视觉焊道缺陷检测；
- 数据公开，代码和训练模型公开；
- 数据包含低分辨率 `lweld` 和高分辨率 `hweld` 两部分；
- 原论文报告类别不均衡，并提供检测和分类实验；
- 比 X 射线、超声类数据更接近我们的图像输入。

原论文信息：

- 数据规模：3022 张焊道图像；
- 子集：`lweld` 约 2000 张，低分辨率 640×480；`hweld` 约 1022 张，高分辨率 2048×1080；
- 缺陷类别：pores、deposits、discontinuities、stains；
- 原文设置：80% train / 20% test holdout，训练阶段 5-fold cross-validation，保存 50 epochs 内验证性能最好的模型；
- 原文评价：Precision、Recall、F-score；IoU ≥ 0.5 判定 TP；同时报告 mAP。

## 3. 是否拉伸

公开数据集默认不拉伸。

原因：

- LoHi-WELD 图像不是我们的极柱圆环焊道，没有稳定的同心圆 ROI；
- 强行拉伸会改变公开数据原始分布，也不符合原论文设置；
- 为了和公开论文对比，公开数据集实验使用原图检测路线。

因此路线为：

```text
LoHi-WELD 原图
→ 统一 resize
→ D-FINE 检测
→ 候选框/IBO 区域证据
→ 正常参照空间
→ 频率证据
→ 长尾/混淆类纠错
→ 按原论文指标评价
```

## 4. 固定参数原则

为了公平比较，所有方法共用同一组关键参数。

| 参数 | 设置 |
|---|---|
| 检测器 | D-FINE HGNetv2-S |
| 是否拉伸 | 不拉伸 |
| 输入尺寸 | 320×320、640×640、1280×1280；主报告优先 640，补充 320/1280 |
| batch size | 官方 YOLOv7-tiny 训练为 8；D-FINE 根据显存固定，优先 4，若 1280 显存不足则降到 2；同一检测器内所有方法一致 |
| optimizer | AdamW |
| 主学习率 | 0.0001 |
| backbone 学习率 | 0.00005 |
| weight decay | 0.0001 |
| epochs | 50，用于对齐 LoHi-WELD 原论文；如果先做快速验证，可单独标为 pilot |
| 置信度阈值 | 主评价使用 0.001，对齐 LoHi-WELD 官方 `test.sh`；另扫 0.05–0.95 输出 PR/F1 曲线 |
| NMS IoU 阈值 | 0.50，对齐 LoHi-WELD 官方 `test.sh` |
| TP IoU 阈值 | 0.50，用于 P/R/F1，与 LoHi-WELD 原论文一致 |
| mAP | 报告 mAP@0.5；若工具支持，同时报告 COCO mAP@0.5:0.95 |
| random seed | 0，后续可扩展 3 seeds |

说明：

- 我们自己的展开条带模型使用 `[160,1024]`，这是圆环焊道拉直后的专用尺寸，不能直接用于 LoHi-WELD。
- LoHi-WELD 官方 `train.sh` 实际跑 320、640、1280 三档，因此公开数据集主实验采用 640，补充实验保留 320 和 1280。
- LoHi-WELD 官方 `test.sh` 使用 `conf=0.001`、`iou=0.50`，因此主评价也按该阈值执行；0.25 只作为可视化筛选阈值，不作为正式指标阈值。

## 5. 对比方法

| 编号 | 方法 | 作用 |
|---|---|---|
| P0 | LoHi-WELD 原论文 YOLOv7/YOLOv7-tiny 结果 | 作为论文报告值对照 |
| P1 | D-FINE 原图基线 | 检查 D-FINE 在公开数据集上的基础能力 |
| P2 | D-FINE + IBO区域证据 | 检查候选框聚合/区域证据是否有效 |
| P3 | D-FINE + IBO + 正常参照空间 | 检查正常参照是否能帮助缺陷确认 |
| P4 | D-FINE + IBO + 频率证据 | 检查频率纹理证据是否有效 |
| P5 | D-FINE + IBO + 正常参照 + 频率证据 | 主体方法 |
| P6 | P5 + 长尾/混淆类纠错 | 完整方法 |

## 6. 评价指标

与 LoHi-WELD 原论文保持一致：

| 指标 | 用途 |
|---|---|
| Precision | 看误检多少 |
| Recall | 看漏检多少 |
| F-score/F1 | 综合 Precision 和 Recall |
| mAP@0.5 | 与检测论文主指标对齐 |
| per-class AP / per-class F1 | 看长尾类是否提升 |
| macro-F1 | 避免大类掩盖尾类 |
| tail-class recall | 重点看长尾缺陷召回 |

判定规则：

- IoU ≥ 0.5 且类别正确：TP；
- IoU < 0.5：定位错误；
- IoU ≥ 0.5 但类别错误：错类；
- GT 没有匹配预测：漏检；
- 没有对应 GT 的预测：误检。

## 7. 长尾分析方式

先统计训练集每类实例数，再定义尾类。

建议两种口径都保留：

1. 数据驱动尾类：训练实例数排名靠后的 30% 类别；
2. 阈值尾类：训练实例数低于中位类别实例数的 30%。

输出：

- 类别分布柱状图；
- head / medium / tail 三组指标；
- 尾类混淆矩阵；
- 尾类被头类吸收的典型图。

## 8. 正常参照空间在公开数据集上的构建

LoHi-WELD 可能没有显式无缺陷类别，因此采用两种方案：

| 方案 | 做法 |
|---|---|
| N1 | 从标注框外的焊道区域采样正常 patch |
| N2 | 如果数据集中存在无缺陷图，则优先使用无缺陷图采样 |

不能把测试集正常区域放入正常参照库。正常参照库只从训练集构建。

## 11. 风险与注意事项

- LoHi-WELD 的公开指标来自 YOLOv7，不是 D-FINE，因此我们要分清“原文报告值”和“我们复跑值”。
- 如果无法完全复现原文 5-fold，需要标注为 fixed split 实验，不能声称完全复现。
- 公开数据集没有圆环结构时，不能使用我们的 150px 展开滑窗训练。
- 正常参照库必须只用训练集构建，避免数据泄漏。
- 所有方法必须共享同一 resize、学习率、epoch、阈值扫描范围。
